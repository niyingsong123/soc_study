# IO12：PCIe AER：严重性、报告权与恢复触发

## 错误分类的对象

可纠正错误由协议/硬件恢复，不要求软件启动相同级别的恢复；仍可记录用于诊断。不可纠正非致命错误使某事务不可靠但链路仍可工作，致命错误则使链路可靠性受到破坏。该分类属于 PCIe 接口影响，不能与 UMC CE/UE 一一对应。

AER 驱动关联有相应能力的 Root Port/RCEC，日志可包含来源、状态/mask、首错及 TLP header。报告来源 ID 是诊断线索，不能单凭 ID 就断言那个设备是物理故障根因。

## 谁负责处理

Linux 需要固件通过 ACPI _OSC 授予 AER 控制权，避免固件和 OS 同时处理同一状态造成不可预测行为。能力存在、报告使能、处理所有者及驱动恢复回调是四个不同条件。

非致命错误通常不要求上游链路 reset；致命路径通知 frozen 并需要相应 reset_link 支持，再按恢复结果进入后续阶段。没有 handler 或必要复位支持会使恢复失败，不能把“日志打印出来”当作已修复。

## 微架构研究如何利用

将物理/协议检测、AER 状态保存、上游错误消息、软件回调和恢复重建分别标注。保存错误与第一次失败事务的关系、后续请求是否停止、诊断信息何时清除。[IO9](../../PCIE/sources/IO9-pci-error-recovery.md) 是完整恢复协调的参照，[MEM6](../../PHY/sources/MEM6-pcie-equalization.md) 是 PHY 训练背景；此页不提供 AMD NBIF 内部重放队列的实现。
