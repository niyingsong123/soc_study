# MEM3：AMDGPU RAS：错误计数、坏页与恢复策略

更新日期：2026-09-24。

导读：从软件侧梳理 CE/UE、坏页状态和恢复动作，适合连接 UMC 检测、IH 通知及页面隔离；不能用软件状态替代硬件错误定位。
来源：[Linux 6.12 AMDGPU RAS](https://docs.kernel.org/6.12/gpu/amdgpu/ras.html)。
阅读状态：已读文档正文的支持、控制、计数和坏页接口；未执行注错、复位或 EEPROM 操作。

## 可见接口与硬件范围

RAS 支持按 ASIC 和 IP block 区分；文档列出功能不表示任意芯片均实现。错误计数可按 block 读出 CE/UE，控制与注错另有接口。设计研究应先列“谁检测、谁累计、谁搬运状态、谁决策”，再关联 sysfs/debugfs，不应把统一软件目录画成统一硬件控制器。

CE 表示此报告路径认定为可纠正，UE 表示不可纠正分类；两者都不是完整故障根因。一次底层错误可能造成多项记录，同一寄存器也可能采用锁存标志而非逐事件计数。[MEM14](../../UMC/sources/MEM14-umc810-ras-address.md) 的代码给出具体代际的分类条件，不能只凭名字换算错误发生次数。

## 坏页生命周期

bad_pages 记录 GPU page frame、页面大小和状态；R 表示已预留，P 表示等待处理，F 表示预留失败。P 不能解读为该页已经从所有访问路径安全移除；F 也不能被统计成隔离成功。隔离研究应跟踪页面是否仍被映射、是否存在在途访问以及恢复后的重新分配。

部分设备利用 EEPROM 保存坏页信息，以便重启后继续规避。清除这类记录只改变软件/持久化名单，不会修复存储单元。文档提到 UE 通常触发 GPU reset，不可恢复情形可受自动重启配置影响；不能据此声称所有错误都只有一种复位范围。

## 跨模块使用方式

可将流程拆成 UMC/其他 block 检测、状态保留、IH/轮询传递、驱动读取、错误地址转换、坏页预留、恢复重建。对每一步分别写清状态所有者、是否丢失信息、何时清除、是否可重试。

需要重点追问：通知丢失时是否仍有锁存状态；UE 无有效地址时如何处置；复位是否保留坏页名单；多通道计数是否可比较。它们是研究问题，文档没有给出所有答案。与 [MG6](../../IH/sources/MG6-ih60-ring-hardware.md) 的事件 ring、[MEM14](../../UMC/sources/MEM14-umc810-ras-address.md) 的地址有效位和 [MG11](../../RSMU/sources/MG11-umc67-ras-comparison.md) 的不同 UMC 实现联读，避免把完整 RAS 系统归给 RSMU 一个缩写。
